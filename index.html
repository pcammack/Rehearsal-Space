WHAT'S NEW IN v10.2
· Journal reworked: one component, three scopes. Universal notes and piece notes were two separate boxes competing for attention; now there's a single journal with a Universal / Collection / Piece switcher, defaulting to whatever you're currently looking at. Collection is new — a collection's own journal, tracking whichever collection the library's "Filter:" is currently set to, with no separate picker to keep in sync. No mood pickers, no required fields — same free-text box as before, just one of them instead of two (plus the new collection one).
· Expand-to-write. A small ⤢ button opens the journal in a larger, quieter overlay for real thinking, then closes back into the compact box with no ceremony — same text, same autosave, either way.
· Journal entries are now individually dated under the hood. Paragraphs (separated by a blank line, exactly how you'd write anyway) are tracked with their own first-written date, foundational plumbing for progress views later — nothing surfaced yet, this just starts capturing it.
· Today's intention now lands as its own paragraph instead of an extra line tacked onto whatever came before it, so it gets its own date like anything else you write.
WHAT'S NEW IN v10.1
· Default mark view is now "All" instead of "Structural". Applied both on cold load and on opening any piece — no more auto-guessing based on whether structural marks exist.
· Tempo is now remembered per passage. Previewing or looping a passage restores the last speed you practiced it at; adjusting the slider (or [ ]) while a passage is active saves that speed back onto it. A passage with no stored speed yet just keeps whatever tempo is already playing, rather than resetting to 100% — so splitting or merging passages as they evolve doesn't lose or orphan anything. Woodshed's own stepped-tempo ladder is unaffected — it doesn't read or overwrite a passage's remembered speed.
· Fixed: waveform could visually misalign with marks when zoomed in close. The waveform was always drawn from a fixed 2,000-bucket downsample of the whole track, so at deep zoom each bucket could span many screen pixels, visually smearing/quantizing the waveform relative to marks (drawn from exact timestamps). Past a certain zoom threshold, peaks are now read directly from the raw decoded audio for just the visible window instead, keeping the waveform pixel-accurate against marks at any zoom level.
· Cleaned up the leftover static "v9.12"/"v10.0" text sitting in the raw HTML for the header badge and this label — both are now blank in source and filled in only by APP_VERSION at load, so there's no stale text to glimpse even before the script runs.
WHAT'S NEW IN v10.0.1
· Piece-organization audit and redesign. A full audit of every piece-level control (architecture, metadata, collections, sync tools) turned up real redundancy and real bugs — this release acts on the findings.
· Library architecture removed, folded entirely into Collections. Library only ever offered exclusive, single-value membership; the actual need (genre + function + event, all at once) was always multi-membership, which Collections already did. A data check confirmed the feature had gone essentially unused. Removed: library CRUD, the per-row library dropdown/color-coding, and the grouped/collapsible list view — the list now always renders flat.
· "Connect local folder" removed entirely. A whole parallel, single-device persistence system that predated cloud sync and had gone unused since. Regular OS file browsing covers audio uploads instead.
· "Merge duplicate libraries/collections" removed — confirmed one-time migration tool for a cloud-merge bug fixed back in v9.2.
· Consolidated Manage panel. The old ⋯ tools menu, the separate "Manage libraries & collections" panel, and the standalone Storage usage toggle — three collector zones — are now one panel, three labeled sections (Collections / Data & Sync / Storage).
· Archived pieces now show inline (dimmed, sorted to the bottom, via the new "📦 Archived" toggle next to Sort) instead of a separate panel — restore or delete right on the same row.
· Collections can be created inline, right from the "+" picker used to assign them to a piece — no round trip to Manage for the thing you'll do constantly. Includes a brief undo affordance.
· Icon meaning standardized app-wide: 📦 always reversible, ✕ always permanent. Collections previously used ✕ for archiving — now matches pieces.
· "Sync now (manual)" removed as a standalone button, folded into the cloud status badge — click it on a sync error to retry.
· New "Recent" sort, using last-practiced data already shown on every row.
· Collection filter now labeled ("Filter:") — it became the primary slicing tool once Collections absorbed Library's old job too.
· Fixed: the sign-in banner's stale "data still saves locally only" copy — cloud sync has been fully automatic since v9.0.
· Documentation split: full version history before v9.11 moved to CHANGELOG-v10.0.1.md — see the note just below. Also removed the unused Workflow/Marker Naming/Keyboard reference block.
WHAT'S NEW IN v9.12
· Fixed: "☁ Sync all pieces now" could leave the currently-open piece looking stale even when it pulled a real update. The bulk pull only ever wrote to localStorage — deliberately, since it's built to loop over pieces you're not currently looking at, and never touches live playback state for those. But if the piece it just pulled a newer copy of was the one you had open at the time, the on-screen notes/markers/passages sat unrefreshed until you closed and reopened that piece or reloaded the page — the pulled data was saved correctly, just not visibly reflected. Bulk sync now also refreshes the visible fields when the currently-open piece is the one it just updated.
WHAT'S NEW IN v9.11
· Fixed: the practice journal could miss cross-device updates for an entire session. Every other synced field gets rechecked against the cloud each time you open a piece; the journal previously only checked at sign-in/page-load, when you typed into it yourself, or via manual "↻ Sync now" — so a browser tab left open (not reloaded) had no way to learn about a journal edit made elsewhere, no matter how many pieces you opened or synced in the meantime. Opening any piece and "☁ Sync all pieces now" now also trigger the journal's existing conflict-safe merge check. No change to the merge logic itself (still safe-pull / safe-push / keep-both-on-conflict, per v9.8) — just added the missing trigger.
